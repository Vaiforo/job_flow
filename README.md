# Job Flow

Job Flow начинается с браузерного сборщика данных для будущего агрегатора вакансий.
Пока он работает с демонстрационным источником
[Quotes to Scrape](https://quotes.toscrape.com/scroll): открывает страницу в Chromium,
дожидается загрузки цитат и прокручивает её до конца. Сбор вакансий ещё не реализован.

Результат сохраняется в `out/result.json`. У каждой цитаты есть текст (`text`),
автор (`author`) и список тегов (`tags`).

## Подготовка и разработка

Нужны Git, Docker с BuildKit, GNU Make и Bash. Docker должен быть запущен.
Node.js, Chromium и библиотеки браузера устанавливаются внутри образа,
поэтому отдельно на компьютере они не нужны.

Клонируйте репозиторий и откройте его каталог. Все команды ниже выполняются
из корня проекта. Если Docker требует прав администратора, используйте
`sudo make` вместо `make`.

Для локальной разработки редактируйте файлы в `src/`, затем повторяйте
`make build` и `make run`. После правки кода зависимости и браузер берутся
из кеша, если он сохранён. Первая сборка требует интернета и занимает больше времени.

## Сборка и запуск

```sh
make build
make run
```

Первая команда собирает production-образ `job-flow:latest`, вторая запускает
сборщик. Каталог `out/` подключается к контейнеру, поэтому JSON остаётся на
компьютере после его завершения. При запуске через `sudo make` результат
принадлежит исходному пользователю, а не root.

Образ собирается от `node:22-bookworm` в три стадии: npm-зависимости,
браузерная среда и приложение. Системные библиотеки и Chromium устанавливаются
отдельными шагами, исходники копируются последними.

## Проверка и очистка

```sh
make ci
```

Собирает образ, запускает сборщик и проверяет, что результат содержит непустой
валидный JSON с цитатами. После проверки удаляет образ и `out/`, в том числе
при ошибке. GitHub Actions выполняет эту же команду. Для сбора данных нужен
доступ к сайту источника.

Для отдельной очистки:

```sh
make clean
```

Кеш сборки сохраняется: следующая сборка с теми же зависимостями не скачивает
браузер заново. Исходники очистка не затрагивает. Каталог `out/` не попадает в Git.
